## TB-S-1: Image URL is fetched safely

**Category:** bug. **Status:** done 2026-10-16 (`b521a23` — verified on main; only test gaps remained). **Priority:** P1. **Blocked by:** DD-S-1 (the branch is the base; this ticket verifies it and closes gaps).

On `main`, `POST /api/launch` takes `imageUrl` and the IPFS helper fetches it with a plain `fetch`, buffers the whole body with `arrayBuffer()`, and pins the bytes under the service's storage key. There is no scheme, host, private-IP, redirect, size or content-type check, and a URL already containing `/ipfs/` is passed through untouched into the metadata `image` field. An agent can make the service fetch loopback or link-local addresses and publish the result, exhaust memory with a large body, or point the metadata image at any host. Evidence: `src/app/api/launch/route.ts`, `src/lib/ipfs.ts` (`uploadImageFromUrl`), plan section 4.

Done when:
- [x] Verified on the branch, with any gap fixed: the image fetch accepts http(s) only, vets every resolved address (loopback, private, link-local, CGNAT, NAT64, multicast refused), pins the connection, follows redirects only manually with per-hop vetting and a hop bound, streams under the byte cap, and sniffs magic bytes for PNG, JPEG, GIF and WEBP; failures return a 400 naming the rule, never the upstream body. `[verified 2026-10-16: all already in `src/lib/image-fetch.ts`/`upload.ts` — rule refusals 400, upstream failures 502 (the deliberate split the branch's tests pin).]`
- [x] A pre-existing `/ipfs/` URL is not passed through; it is fetched and re-pinned under the same rules or refused. `[implemented: fetched through the guard and re-pinned (`launch.ts`); `ipfs://` refused as non-http(s); tests added.]`
- [x] Verified on the branch: bytes and metadata go through the backend upload proxy with the caller's IP forwarded (so per-caller buckets, moderation, brand and geo rules apply), and no Filebase credential remains in this service's env contract or `DEPLOY.md`. `[verified: `backendPostForm`/`backendPostJson` forward the first XFF hop; no storage credential anywhere.]`
- [x] Launch metadata built by the service always declares a top-level `launchType` matching the chosen category, so backend TB-B-6's fail-closed rule on a missing type never gates a service launch by the host's region. `[implemented: `launchType: input.category` unconditional; per-category test added.]`
- [x] `tests/image-fetch.test.ts` covers: private address refused before any connection, redirect-to-private refused, oversized body aborted at the cap, wrong content type refused, a valid public PNG succeeds against the recorded proxy fixture; missing cases are added.

## TB-S-2: First-buy amount is converted in the config's quote units

**Category:** bug. **Status:** done 2026-10-16 (`079bbd6`+`d7aa991`). **Priority:** P1. **Blocked by:** DD-S-1 (the branch is the base; this ticket verifies `src/lib/first-buy.ts` and closes gaps).

On `main`, the launch route converts `buyAmountSol` with `Math.round(value * 1e9)` and passes it as the first-buy amount in quote atoms. The hardcoded config is USDC-quoted with 6 decimals, and the prod-indexed config DD-S-1 moves to is SKR-quoted with 6 decimals, so a value of 1 becomes one billion atoms, about a thousand units of the quote token, and SKILL.md's "minimum SOL" guidance is wrong for both. The field name itself promises SOL. Evidence: `src/app/api/launch/route.ts`, `src/lib/dbc.ts` (`buildLaunchTx`), `src/lib/config.ts`, `SKILL.md`. The min-out floor for the first buy is DD-S-2's criterion and is not repeated here.

- [x] Verified on the branch, with any gap fixed: the first-buy amount is accepted as a decimal string in quote-token units under a name that does not say SOL, converted with the live quote mint's decimals read from chain (not a constant), with an integer-safe conversion and a documented upper bound; a legacy SOL-named field is rejected with a 400 that names the quote token. `[implemented 2026-10-16: `getConfigCatalogWithGeo` now ALWAYS reads the quote mint on-chain and chain facts win over the record (record decimals survive a failed read only for recorded SPL mints, which cannot carry extensions); bound documented as u64 max in SKILL.md/skill.json; `unsupported_buyAmountSol` 400 now names `quoteSymbol`. Cost: one `getParsedAccountInfo` per unique quote mint per request (deduplicated by `mintInfoCache`).]`
- [x] The response and both skill documents state the quote token and decimals for the config the launch used. `[implemented: `quoteSymbol` + `quoteDecimals` on the launch response and in all four contract documents.]`
- [x] Tests cover: 6-decimal quote converts exactly, over-bound rejected, non-numeric rejected, and a recorded simulation (`sigVerify: false`) of the built launch transaction shows the expected quote atoms in the first-buy instruction. `[implemented: real `buildLaunchTx` over recorded fixtures (prod pool-config + new `tests/fixtures/skr-mint.getAccountInfo.json` mainnet capture), stub simulate asserted run, DBC `swap` ix decoded: `amountIn` = expected quote atoms.]`
